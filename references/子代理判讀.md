# 子代理判讀

sweep 的線索很多時，可以請子代理先看圖、分類，主 session 再複核。這份規定輸入、回覆格式和複核比例。**子代理的結論只是初判，不能直接交給使用者。**

## 給子代理的輸入

1. **groups.json 的 group 物件**（`sweep-groups.json` 裡 `review` 的組，整個物件貼進去，不是報告裡的一行文字）：要含 `id`、`check`、`kind`、`pages`（含每頁的 `status`、`statusByWidth`）、`worst`、`worstPage`、`worstWidth`、`rect`、`evidence`（證據圖路徑）、`members`、`compareStatus`、`compareDetail`（變差的前後數值）。判斷「新出現／變差」要靠這些欄位，不要讓子代理自己猜。
2. **要讀的判斷檔**：`references/判斷/通用.md`＋這個專案的類型檔（`siteTypes`）＋`SKILL.md`「用眼睛看」的假線索清單。
3. 這次的範圍：網址、哪個版本（label）、哪些 profile／寬度，以及專案已決定「不改」的項目（`acceptedExceptions`、`_不改的設計決定`）。
4. 要看的組 id 清單（每個子代理一批，建議 15 組以內）。

## 回覆格式（固定）

每組一行：

```
組 id｜看了哪張圖／哪個寬度｜判定｜對應哪條判斷規則或原因
```

- 判定只能是：**真問題**、**假線索**、**預期變化**、**要操作才知道**、**沒看**。
- **「沒看」的必須列組 id**，不能空白、不能省略；漏掉的組視為沒看。
- tap（點擊範圍）、內捲區、動態（捲完還透明、進場動畫）三類，**要有操作或量測證據才能判「假線索」**：寫出做了什麼（例如「在 810 寬度用觸控點中心點，命中的是同一連結的外層」、「捲到最底，最後一項看得到」）。只看靜態截圖的，判「要操作才知道」。
- 最後附一行統計：總數＝真問題＋假線索＋預期變化＋要操作才知道＋沒看，和給的組數對得上。

## 主 session 的複核

- 標**真問題**的：**全部複核**（自己開證據圖或整頁圖確認）。
- 標**假線索**的：**抽查至少 20%**（無條件進位）；tap、內捲區、動態三類優先抽。抽到一個判錯，就把那位子代理那一批的假線索全部重看。
- 標**預期變化**的：對照這次的修改內容（`git diff`、PR 說明）確認真的是預期；對不上的當真問題。
- 標**要操作才知道**、**沒看**的：主 session 自己做，或列進「還沒驗的」交給使用者。
- 複核完才進 `SKILL.md`「交給使用者」。
