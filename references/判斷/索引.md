# 設計判斷：依網站類型組合

機器量得到溢出、裁切、點擊範圍，量不到「不好看」。這個資料夾是看截圖時的判斷依據，依網站類型分檔，每個專案挑符合的組起來用。

## 證據強度

> 這裡的實務案例目前幾乎都來自**同一個**多語系內容型網站（四種語言、只有桌機和手機設計稿），還沒在第二個專案驗證過。同一個專案裡的多個頁面、多個問題，不算多份獨立的證據。檢查項目可以跨專案用；偏好和案例的解法，要依你的專案確認。

例外會另外註明：〔跨專案觀察〕（兩個以上的專案都看到）、〔官方文件〕（有瀏覽器或框架的文件支持）、〔待核實〕（還沒查證）。沒有註明的就是單一專案的經驗。

## 怎麼挑

1. **`通用.md` 每次都讀。**
2. 依專案的特性加讀下面符合的類型（可以多選）。挑了哪些寫進專案設定檔的 `siteTypes`，之後的 session 照用。
3. 專案自己的 QA 規則優先於這裡。

| 類型 | 檔案 | 什麼樣的專案 |
|---|---|---|
| 通用 | `通用.md` | 所有專案 |
| 內容型網站 | `內容型網站.md` | 以照片、文章、介紹、卡片為主，形象或導覽網站 |
| 多語系 | `多語系.md` | 有兩種以上語言，特別是中日韓加英文 |
| 無平板稿 | `無平板稿.md` | 設計稿只有桌機和手機，平板由前端推論 |

**待擴充**（還沒做過，遇到時新增一個檔案、加進上表）：
- 表單多：報名、預約、會員（鍵盤蓋住輸入框、日期選擇器、驗證訊息位置）
- 電商：商品格線、篩選、購物車側欄、結帳流程
- 後台、儀表板：寬表格、側欄收合、圖表
- 有平板稿：比對對象改成平板稿，判斷重點會不同

## 標籤

每條前面標用途：

| 標籤 | 意思 | 怎麼用 |
|---|---|---|
| 〔通用檢查〕 | 每個專案都值得檢查的項目 | 檢查；確認真的有影響才列成問題。不代表已經跨專案驗證 |
| 〔偏好〕 | 維護者的預設偏好 | 維護者自己的專案照做，除非專案另有決定；其他人當參考，依自己的專案決定 |
| 〔案例〕 | 單一情境的觀察或決定 | 只當參考。遇到類似情況時提出來問，不要直接套用解法或數值 |

〔案例〕後面註明是哪一種：
- **／維持原樣**：試過或看過，決定不改
- **／設計決定**：使用者在幾種做法裡選了一種
- **／誤報**：以為有問題，確認後沒有
- 沒註明的是一般觀察

## 每條的寫法

**觀察**（看到什麼）→ **選項**（可以怎麼改）→ **反例**（什麼情況不改）。

- 例子裡的數字只描述當時的情況（寫清楚量的是視窗寬、卡片寬還是文字欄寬，單位是 CSS px），不是門檻。
- 不寫專案名稱、頁面名稱、問題編號。
- 新增規則時先放進最具體的類型；在條件相近的第二個專案也成立，才搬到 `通用.md`，並註明〔跨專案觀察〕。
- 反例和成功的修改一樣重要，決定不改的也要寫。

## 維護

- 每條規則的原始來源由維護者另外存一份對照表，不隨 skill 發布。改規則的適用範圍或標籤時，同步改那份對照表。
- 找不到來源時寫〔待核實〕，不要自己提高證據強度。
