# 技術坑

需要哪一節讀哪一節。每條都是在同一個專案（Next.js＋Tailwind v4，2026-11）踩過的，沒有記下瀏覽器和套件的確切版本；不同專案、不同版本可能不一樣，套用前先在專案裡驗。標〔待核實〕的是還沒查證的敘述。

## 瀏覽器與模擬

- **驗證分三層，報告要寫是哪一層**：
  1. Chromium 觸控模擬（`isMobile`、`hasTouch`、iPad Safari UA）：快速掃版面、點擊範圍。
  2. Playwright WebKit：補瀏覽器引擎差異（斷行、`auto-phrase` 不支援等）。
  3. 真的 iPad Safari：網址列收合的高度、真實手勢、影片自動播放、低耗電模式。
  Chrome 換 iPad UA 不會變成 Safari；WebKit 也不等於客戶那台 Safari。
- **確認觸控模擬真的成立**：量 `matchMedia('(pointer: coarse)')`、`('(hover: none)')`。只設 viewport 寬度、沒開 `hasTouch` 時，拍到的是「平板尺寸的桌機」，hover 效果、點擊範圍都不準。
- **平滑捲動套件**（Lenis 等）在觸控模擬下可能關閉或行為不同，捲動量測前先確認。
- **Safari 的可視高度比裝置高度矮**：例如 iPad 第七代直向 1080 → 約 980、橫向 810 → 約 740（網址列；〔待核實〕估計值，沒有實機量）。量「一屏看得到多少」用可視高度。
- **Chrome DevTools 內建的「iPad Mini」是舊款 768×1024**，不是現在的 744。請使用者自己看時，先教使用者加自訂裝置（例如 744×1133）。

## 截圖

- **`page.screenshot` 會等字型**，字型多或很大的頁可能逾時；Chromium 可改用 CDP `Page.captureScreenshot`（`captureBeyondViewport: true`）。但繞過等待不代表字型已載好，要另外確認 `document.fonts.ready`。
- **整頁截圖裡 lazy 的圖片可能是空白**，不是壞掉。先從上捲到底再回來；要確認就捲到那裡拍視窗截圖。
- **開「減少動態」拍時，進場動畫的元素可能一直停在透明**（`opacity: 0`）。這是網站的缺陷，要另外列；改用一般模式拍只是取得證據，不算問題消失。拍之前先列出捲完仍 `opacity: 0`、有文字的元素。
- **藏起固定頁首再拍會藏掉真正的遮擋問題**。預設不藏；要藏時寫進紀錄。主視覺背景如果是 sticky，藏了會變白，改用第一屏截圖。
- **〔待核實〕無頭瀏覽器不會畫出自訂捲軸**：捲軸顏色、寬度用 `getComputedStyle` 量，截圖說明寫「截圖看不到捲軸」。
- **重疊檢查會誤報**隱藏的 tab 面板、固定頁首：要過濾祖先的 `visibility`／`display`。
- **螢幕閱讀器專用的文字**（1px 高）截不到，也不要算進行數。
- **修改後的截圖等文字都定案再拍**；拍完文字又改了，重拍或在紀錄註明。

## 觸控點擊範圍

- **外觀不變、範圍外擴**：Tailwind `pointer-coarse:before:absolute pointer-coarse:before:-inset-y-[10px] pointer-coarse:before:content-['']`（按鈕本身要 `relative`）。
- **驗證用 `document.elementFromPoint`** 點擴出來的那一格，看拿到的是不是按鈕；只量按鈕矩形會低估。
- 擴大後要看相鄰按鈕會不會互相蓋到（例如按鈕之間上下間距 8px，各外擴 4px 剛好碰到、不重疊）。

## Tailwind（v4）

- **`max-[N]` 是「小於 N」**，不含 N：`max-[1179px]` 時 1179 會落到下一段。交界寬度兩邊都要量。
- **混用 `min-[...]` 和具名斷點時，排序可能讓某條蓋不過另一條**。曾遇過 `min-[1180px]:grid-cols-3` 跟 `md:grid-cols-2` 放一起沒呈現三欄（單一案例）。遇到類似情況，先看產生的 CSS 順序、實際斷點值和 computed style，再決定怎麼改寫；當時改成 `lg:grid-cols-3 lg:max-[1180px]:grid-cols-2`，不是固定解法。
- **只套平板**：`md:max-lg:`（`md` 到 `lg` 之間）。改 `md` 斷點要在 `@theme` 改 `--breakpoint-md`，改完量整站。
- **兩個寬度之間線性漸增**：設計需要尺寸在寬度 w₀ 到 w₁ 之間連續變化（w₀ 時是 h₀、w₁ 時是 h₁）時，`h = h₀ + (100vw − w₀) × (h₁ − h₀) ÷ (w₁ − w₀)`。Tailwind 寫法例如 `lg:max-[1440px]:h-[calc(59px+(100vw-1024px)*0.3822)]`（0.3822 = (218−59) ÷ (1440−1024)，數字只是示範）。區間外要另外定義；在兩端、中間、交界各量一次。
- **語系限定**：`[&:lang(zh)]:break-keep`；日文標題 `[&:lang(ja)]:[word-break:auto-phrase]`。
- **hover 只給滑鼠**：v4 的 `hover:` 預設已經包 `(hover: hover)`；自訂 CSS、舊版或第三方元件要自己包。

## Next.js

- **用真的 iPad 連本機 dev server**：`next.config` 的 `allowedDevOrigins` 要加電腦的區網 IP，不然 JS 被擋、圖片停在淡入前，看起來像「圖片沒載出來」。先看主控台和網路請求確認是這個原因。IP 換網路會變；這行只留本機，不 commit。
- **請開發者加版本端點**：新增 `/version.txt`（或頁面 `<meta name="version">`），內容用 `VERCEL_GIT_COMMIT_SHA`，設定檔 `sites.<x>.versionUrl` 指過去。Vercel 部署沒有版本標頭，label 寫的 commit 無法被第二個證據核對；有端點，報告會並列端點回的版本，label 寫錯一眼看得出。端點回 HTTP 401／403（預覽站有密碼保護）時，報告會寫「版本端點回 HTTP N（可能有密碼保護）」，不會默默當成沒有。
- **Turbopack 不跟出專案根目錄的 node_modules symlink**：把 `node_modules` 做成指到專案外的 symlink，`next dev`／`next build`（Turbopack）會找不到套件。要共用一份依賴時改用複製：macOS 用 `cp -cR`（APFS 複製，不多佔空間）。
- **dev／build 可能重新產生索引類的檔案**（例如搜尋用的 json），沒改內容時 commit 前還原。

## 改斷點的流程

- 改斷點本身和各頁版面修改分開做、分開提交，說明寫合併順序；各頁版面的預覽要合上斷點的改動再部署，不然看不出效果。
- 改完逐頁量新斷點附近（新斷點本身和往上十幾 px）：溢出、裁切、行數（跟舊斷點比多出來的行），再開彈窗、選單、tab 看是否在畫面內。外語頁也要量。
