# 執行規格：設定檔、量測定義、結果格式

`scripts/shots.mjs`（對照截圖）和 `scripts/sweep.mjs`（量測）共用同一份設定檔。設定檔放在專案裡（例如 `qa/<資料夾>/tablet-qa.json`），不要存回 skill。

## 執行

下面的 `<skill 資料夾>` 是這個 skill 實際所在的資料夾（個人 skill 通常是 `~/.claude/skills/tablet-qa`，裝成外掛或專案 skill 則在別處）；Claude 用 skill 實際載入的路徑，不要照抄範例。

```bash
node <skill 資料夾>/scripts/sweep.mjs qa/tablet/tablet-qa.json
node <skill 資料夾>/scripts/sweep.mjs qa/tablet/tablet-qa.json home about --profiles=ipad102-portrait   # 小範圍：頁面 id 可用位置參數或 --pages=home,about
node <skill 資料夾>/scripts/shots.mjs qa/tablet/tablet-qa.json spec-dialog card-grid          # 只跑這幾項：案例 id 可用位置參數或 --cases=spec-dialog,card-grid
node <skill 資料夾>/scripts/shots.mjs qa/tablet/tablet-qa.json --site=after --baseline=20261104-0900-pr12   # 合併後只重拍 after
```

- Playwright 從哪裡載（依序）：設定檔的 `playwrightFrom`（**相對於設定檔所在資料夾**，指到有裝 playwright 的專案資料夾，或放著 `playwright/` 套件的資料夾）→ 設定檔所在資料夾往上找 `node_modules` → 目前工作資料夾往上找。都沒有就報錯並提示 `npm i -D playwright`。
- 瀏覽器：設定檔頂層選填 `browser`，只影響 `engine` 是 chromium 的 profile 和前後對比圖的合成（profile 設 `engine: "webkit"` 仍用 Playwright WebKit，要另外 `npx playwright install webkit`）。值打錯字會在讀設定檔時報錯（結束碼 2），並列出可用值。

  | `browser` | 意思 |
  |---|---|
  | `"auto"`（預設，可不寫） | 先用系統的 Google Chrome。**只有**找不到 Chrome 時（Playwright 說 `distribution 'chrome' is not found`）才改用 Playwright 內建的 Chromium，並印一行「找不到 Google Chrome，改用 Playwright 內建的 Chromium」。其他錯誤（權限、缺系統函式庫、逾時、崩潰）原樣報錯，不換瀏覽器 |
  | `"chrome"` | 只用 Google Chrome，失敗就報錯，不換 |
  | `"msedge"` | 只用 Microsoft Edge，失敗就報錯，不換（目前沒有實測過） |
  | `"bundled"` | 只用 Playwright 內建的 Chromium（`npx playwright install chromium` 下載），失敗就報錯，不換 |

  兩個都沒有時，錯誤訊息會說明要在哪個資料夾執行 `npx playwright install chromium`（這會下載測試用瀏覽器，不會改網站）。錯誤訊息保留 Playwright 的完整原文。
- **紀錄實際用的瀏覽器**：版本字串帶通道，例如 `chrome 131.0.x`、`bundled-chromium 131.0.x`、`msedge …`（WebKit 只有版本號）。連同 Playwright 版本、`process.platform`／`process.arch`、設定的 `browser` 和是否備援，寫進 `run-meta.json` 的 `env`、`shots-results.json`／`sweep-results.json` 的 `tool`，和報告開頭的「工具」行；備援時工具行會註明。
- **shots 比對基準時也核對瀏覽器**（sweep 本來就核對工具版本）：基準和本次的瀏覽器通道或主版本不同，報告開頭和對比圖頁尾會警告「執行環境不同（基準：X，本次：Y），差異可能來自瀏覽器」；基準是舊版腳本跑的、沒有記瀏覽器通道，則寫「無法核對」。只警告，不阻擋，也**不放進 `condHash`**（Chrome 自動更新不該讓所有基準失效）。
- 前後對照盡量用同一台機器、同一個瀏覽器。內建 Chromium 不能播 H.264（mp4）影片，有影片的頁面可能跟 Chrome 量到的不一樣；跨作業系統（macOS、Linux、Windows）字型不同，行數和寬度都可能變。
- **量測本身不改網站程式，但操作步驟（點擊、填表、送出）可能在網站上產生資料。** 電商、表單請用測試環境和測試資料，不要把 steps 指到正式站的送出、下單、付款按鈕；`fill` 填的內容也不要用真實個資。**`press` 的 `Enter` 在輸入框裡會送出表單**，`fill` 也可能觸發網站自動儲存。
- 結果預設寫在設定檔旁的 `tablet-qa-runs/`（設定檔 `out` 可改）。這個資料夾會越長越大，請加進 `.gitignore`，也不要指到會被部署的資料夾（例如 `public/`、`qa-assets/`）。

### 結束碼

| 碼 | 意思 |
|---|---|
| 0 | 全部成功（沒有失敗，也沒有證據不完整） |
| 1 | 有頁面或案例失敗（打不開、操作失敗、截圖失敗），或輸出前核對「預計筆數 = 實際筆數」沒過 |
| 2 | 命令列或設定檔有問題（不認得的旗標、`--jobs` 不是 1–16 的整數、id 重複或含不合法字元、找不到 Playwright 等），沒開始跑 |
| 3 | 起跑前檢查（smoke）沒過 |
| 4 | 沒有失敗，但有 `incomplete`（證據不完整）。終端機最後會用 `**證據不完整 N 項（不能當通過…）**` 醒目列出。有失敗時仍回 1 |

`--baseline`／`--compare` 指到沒跑完的 run 也是結束碼 2（見「每次執行獨立的資料夾」）。0 = 全部成功。

### 共同選項

| 選項 | 說明 |
|---|---|
| `--site=before\|after\|both` | 量／拍哪個網站。設定檔只有一個網站時，不用寫，直接用那個。sweep 預設 `after`（沒有就用唯一的那個）；shots 預設設定檔裡所有網站 |
| `--run=名稱` | 這次結果的資料夾名。預設 `YYYYMMDD-HHmm-<網站 label 的英數字>`（label 全是中文時沒有英數字，就用 `before`／`after` 當名稱，所以建議自己用 `--run` 取名）；同名已存在就加 `-2`。指定既有名稱會寫進同一個資料夾、不避讓（例如 shots、sweep 想放在一起），所以每次用新名。同名會被擋：shots 的 `--run` 不能和 `--baseline` 同名、sweep 的 `--run` 不能和 `--compare` 的 run 同名（結束碼 2，在建立資料夾前就停）。名稱不能是 `.`、`..`，不能含斜線和 `: * ? " < > |` |
| `--no-smoke` | 跳過起跑前檢查 |
| `--compare=<run 資料夾名>[:<site 名>]` | 只有 sweep。跟舊 run 比對，找出「只在新版本出現」的線索（見下面「新舊比對」）。不用重量舊版本 |
| `--notify` | shots、sweep 都可用。跑完（或被中斷）時跳一則系統通知；設定檔頂層 `"notify": true` 同效，旗標優先，`--notify=false` 可關。預設關。內容：`<tool> <run> 量完，待判讀：完成 a、證據不完整 b、失敗 c`（被中斷：`被中斷：完成 a／預計 n`），不寫「通過」。macOS 用 osascript，第一次會以「工序指令編寫程式（Script Editor）」名義出現，可能要在系統設定允許一次；Linux 有 `notify-send` 才發；其他平台略過。發不出去只印一行 `通知沒發出去：…`，不改結束碼，逾時 5 秒 |
| `--jobs=N` | shots、sweep 同時開幾個分頁（預設 3，只收 1–16 的整數）。shots 並行時終端機依完成順序印，但 `shots-results.json` 與報告一律依設定檔 case 順序（case → profile → site），不受並行影響 |
| `--checks=a,b,c` | 只有 sweep。只跑指定的檢查：`overflow`、`clipped`、`scrollbox`、`tap`、`invisible`、`fixedCover`、`lineJump`、`sizeJump`、`shortLastLine`（逗號分隔）。`--checks=regression` = 回歸預設集（`overflow`、`clipped`、`scrollbox`、`tap`、`invisible`、`fixedCover`），可以和別的混用（`regression,sizeJump`）。沒給 = 全部都跑（相容舊行為）。不認得的名稱報錯（結束碼 2）。報告開頭寫這次跑了哪些、沒跑哪些；`sweep-results.json` 的 `args.checks` 也記下。沒跑的檢查沒有線索，不代表沒問題 |

不認得的旗標（多半是拼錯）會直接報錯結束，不會默默用預設範圍跑。

### 起跑前檢查（smoke）

兩支腳本在展開整個矩陣前，先用第一頁（shots 是第一個案例）和第一個 profile（再加第一個觸控 profile）做三件事：瀏覽器能不能啟動、頁面 HTTP 是否小於 400、觸控模擬是否生效（`pointer: coarse`、`hover: none`）。任何一項不成立就用中文訊息停下來（結束碼 3），說明是「瀏覽器沒有啟動」「第一頁打不開／回 HTTP n」還是「觸控模擬沒有生效」。第一頁本來就是錯誤頁（例如要測的就是 404／500 頁）：在那個案例或頁面寫 `expectedStatus`（見下面），smoke 和正式量測都會把符合的狀態碼當成正常頁面；不需要為此用 `--no-smoke`。`--no-smoke` 只是跳過起跑檢查，**正式量測遇到沒列入 `expectedStatus` 的 HTTP ≥ 400 一樣會標失敗**。

### 每次執行獨立的資料夾

每次 shots 或 sweep 都寫到 `<out>/<run>/`（程式會確認解析後的路徑都在這個資料夾內，且彼此不撞名），並在 `<out>/runs.log` 追加紀錄（舊版的 `latest.txt` 已不再寫）。**不會跟前一次的結果合併**：只重跑幾個案例，資料夾裡就只有那幾個。要拿舊結果比對，用 `--baseline=<舊資料夾名>`。`<out>` 底下直接放的舊檔（本版之前的格式）不會再被讀寫。

每個 run 資料夾還有三份「跑得完不完整」的紀錄：

- `run-meta.json`：`{ run, tools: { shots 或 sweep: {...} } }`。每個工具一份（`--run` 同名讓 shots、sweep 共用資料夾時各記各的）：`args`、`startedAt`、`pid`、`expected`（預計筆數）、`sites`（url、label）、`configSnapshot`（`tablet-qa-config.json`，makeRun 時就複製）、`status`（`running` 起跑時寫入；`done` 跑完，含有失敗項目；`interrupted` 被 Ctrl-C、kill 或對話關掉（SIGHUP）結束；`abandoned` 行程不見了、又沒留下結束紀錄（見下面「起跑時檢查」）；`failed` 筆數對不上等內部錯誤）、`finishedAt`。
- `progress.jsonl`：每完成一筆 append 一行（shots：案例、profile、site、status；sweep：頁、site、寬度、kind、status）。
- `<out>/runs.log`：全部 run 共用，一行一事件，`時間 | 工具 | run 名 | sites 的 url | args | pid | 狀態`，狀態是 `start`，結束時 `done`／`fail`（有失敗項目）／`interrupted`／`fail 紀錄數對不上`。程式被 `kill -9` 或斷電時只會有 `start` 沒有結尾，這就是「沒跑完」的證據。
- **讀別人的 run 前會先檢查**：`--baseline`（shots）、`--compare`（sweep）指到的 run，若 `run-meta.json` 裡該工具的 `status` 不是 `done`，報錯「這個 run 沒有跑完（預計 N、完成 M…）」並以結束碼 2 停下，不拿殘缺的結果當基準。沒有 `run-meta.json` 的舊 run 無從核對，照舊放行。
- **起跑時檢查上次沒跑完的 run**：`makeRun` 建本次資料夾前，掃 `<out>` 下一層每個 `run-meta.json`，找 `status` 還是 `running` 的。行程已不在（`pid` 不存在或沒寫）的：終端機印「注意：… 有 N 個沒跑完的 run」和每個的 run、工具、開始時間、完成 M／預計 n；meta 改成 `abandoned`、`finishedAt` 寫偵測時間，`runs.log` 補一行 `abandoned (detected by <本次 run>)`（下次不再報）；清單也寫進本次報告開頭的「上次沒跑完的量測」。行程還在的（別的終端機正在跑）只印一行，不改。不影響結束碼。`abandoned` 跟其他非 `done` 一樣，不能當 `--baseline`／`--compare`。
- `--resume=<run>`（接續中斷的 run）目前沒有做，之後可能加；現在中斷了就整個重跑，或只用 `--cases`／`--pages` 補跑缺的。
- `--run` 名稱以 8 位數字開頭（視為日期）但不是今天時，會警告一句。

兩支腳本的 JSON 最外層都有 `run`、`time`、`sites`、`tool`。

- `sites.<名稱>` 記 `url`、`label`，以及兩組網站資訊：
  - `version`：**真的能對應到某個版本的證據**——`x-vercel-deployment-url`、`x-deployment-id`、`x-github-sha`、`x-version` 標頭、`<meta name="version">`，以及設定檔該網站的 `versionUrl`（一個回傳版本字串的網址，例如 `/version.txt`）。讀不到是 `null`（不算失敗）。`label` 是人手寫的，`version` 是第二個證據，兩個對不上就先查。
  - `requestInfo`：`x-vercel-id`、`server`、HTTP 狀態。**這只是「這次請求」的識別碼，不能拿來確認是哪一版程式。**報告把它標成「請求資訊（不能當版本）」。
- `tool`：`scriptHash`（skill 腳本內容的雜湊）、`playwright`（版本）、`browsers`（實際啟動的瀏覽器版本）、`configSnapshot`（當次設定檔另存在 run 資料夾的 `tablet-qa-config.json`），方便日後重現。

### Stop hook（選用）

`scripts/hooks/stop-running.mjs`：Claude 要結束回覆時，若還有背景工作在跑 `shots.mjs`／`sweep.mjs`，擋一次，請 Claude 先告訴使用者「還在跑、大約還要幾分鐘、跑完會回報、對話關掉會被中止」。

- 每個背景工作只提醒一次（記號放 `<系統暫存>/tablet-qa-hook/<session_id>/`）；`stop_hook_active` 為 true、沒有符合的工作、或 stdin 讀不懂，都不擋。
- 它只是提醒，**不能阻止**使用者關對話或中止；要跑超過 10 分鐘的量測，請改用終端機分頁（見 SKILL.md「完整驗收」）。
- 背景工作的 status 字串目前接受 `running`、`pending`、`in_progress`。要確認實際值：設環境變數 `TABLET_QA_HOOK_DEBUG=1`，收到的 stdin 會附加寫到 `<系統暫存>/tablet-qa-hook/last-stdin.json`。
- 安裝：加進 `~/.claude/settings.json`（或專案的 `.claude/settings.json`）。路徑以裝在個人 skill 為例，裝在別處要改路徑：

```json
{ "hooks": { "Stop": [ { "hooks": [ { "type": "command", "command": "node \"$HOME/.claude/skills/tablet-qa/scripts/hooks/stop-running.mjs\"", "timeout": 10 } ] } ] } }
```

這是 macOS／Linux shell 的寫法（`$HOME` 由 shell 展開）。Windows 的 shell 不一定會展開 `$HOME`，請改成寫死的完整路徑（例如 `node \"C:\\Users\\<你>\\.claude\\skills\\tablet-qa\\scripts\\hooks\\stop-running.mjs\"`），Windows 沒有實測過。hook 認得的背景指令是「資料夾名以 `tablet-qa` 開頭」的 `scripts/shots.mjs`、`scripts/sweep.mjs`，所以從 GitHub 下載 zip 解開的 `tablet-qa-main` 也可以。

### notify

頂層 `"notify": true` 等於每次都加 `--notify`（跑完跳系統通知，見「共同選項」）。旗標優先：`--notify=false` 可關。選填，預設關。

### sites

`before`（修改前基準）和 `after`（要驗的版本）都是選填，**至少要有一個**。只有一個網站時，shots 只拍那個，sweep 量那個，報告沒有「前後」欄。要做前後比對才需要兩個，或先拍修改前的 run 再用 `--site=after --baseline=` 比（單站做法見 SKILL.md「修改前後對照」）。單站 `--site=after` 可以用。用單站基準時報告會有兩個預期的提示：「基準和本次用了同一個網址」（確認基準拍在修改前即可）、「基準沒有 before」／表格「找不到這一項」（基準本來就只有 after），不是錯。`networkIdleMs`（選填，毫秒，預設 3000）是這個網站等 networkidle 的上限。**舊版有獨立網址時（方式 A），before 網址要用每次部署的唯一網址**（Vercel 是 `<專案>-<hash>-<team>.vercel.app`），不要用會跟著新部署移動的別名或正式網址；`label` 寫 commit、確認時間、從哪裡確認的。`versionUrl`（選填）是回傳版本字串的路徑（例如 `/version.txt`，內容用 `VERCEL_GIT_COMMIT_SHA`）；網址或版本端點回 HTTP ≥ 400 時（可能有密碼保護），報告該網站那一行會寫「版本端點回 HTTP N（可能有密碼保護）」，`sites.<名稱>.issues` 也記下，不會默默變成沒有版本證據。`url` 可以帶子路徑（`https://host/app`），案例的 `path`（`/zh/about`）會接在子路徑後面。`sites` 底下 `_` 開頭的鍵（例如 `_備註`）會忽略。

### out、playwrightFrom（以及路徑一律相對於設定檔）

- `out`：結果資料夾，相對於設定檔所在資料夾，**預設 `tablet-qa-runs/`（在設定檔旁）**。記得加進 `.gitignore`。
- `playwrightFrom`：相對於設定檔所在資料夾（寫絕對路徑換機器就壞掉）。**建議指到含 `node_modules/` 的專案資料夾**（腳本會從那裡的 `node_modules/playwright` 載入）；直接指到改名的套件資料夾（內容是 `playwright/` 套件本身）只是備援。pnpm 專案指到專案根目錄，不要指進 `node_modules/.pnpm/...`。

### tabletMin（最低斷點的 b−1 是手機版）

預設等於 `breakpoints[0]`。寬度**低於** `tabletMin` 的量測（例如最低斷點 744 的 b−1 = 743）仍然會量，但線索標「手機版（參考）」，列在報告主清單後面的參考段，沒有證據圖，不算進「需要看」。要連手機版也當成驗收範圍，把 `tabletMin` 設成 0 以外的更小值（例如 320）。

### compareLabels

`compareLabels: { "before": "修改前", "after": "修改後" }`（選填）：shots 前後對比圖標題列的文字，預設就是「修改前」「修改後」；site 的 `label` 接在冒號後面（例如「修改前：PR #12 預覽」）。

### compareLang

`compareLang`（選填，頂層）：`"zh-Hant"`（預設，省略同此）或 `"en"`，其他值會 exit 2 並列出可用值。**只管**對比圖上腳本自己寫的固定字：標題列的 Before／After（或修改前／修改後）、基準前綴、頁尾（分隔符、「框」、高度、超出提示）、橘字警告，en 時字型也改成拉丁字型優先。**不管**：報告 md、終端機、run-meta、`diffs`、`envWarn` 的語言；也不翻譯使用者自己寫的文字（site 的 `label`、case 的 `note`、`capture.label`、網址、基準 run 名稱），它們原樣畫在圖上。en 的橘字不逐句翻，只畫固定短句（`Baseline conditions differ`、`Test environment differs`、`Incomplete evidence: do not use for judgment`），細節看 `shots-report.md`。不進 `condHash`／`reqHash`，不影響基準比對，舊 run 的圖不會改。

和 `compareLabels` 的關係：`compareLang` 決定固定字的語言，也決定 `compareLabels` 沒寫時的預設標籤；`compareLabels` 有寫（非空）就逐鍵以它為準，標題與頁尾的高度說明共用同一組標籤。

### siteTypes

這個專案適用哪幾類設計判斷（`references/判斷/` 的檔名，不含 `.md`；`通用` 一律會讀，不用寫）。腳本不讀這個欄位，是給 Claude 和使用者看的。

### 以 `_` 開頭的欄位

腳本會忽略（不影響 `condHash`），用來寫說明、裝置來源、不改的設計決定等給人看的備註。

- `_不改的設計決定`：建議寫成陣列，例如 `{ "ref": "T1", "what": "…", "range": "1024–1279", "decidedOn": "YYYY-MM-DD", "by": "使用者" }`。機器量不到的視覺判斷記這裡；sweep 量得到的用 `acceptedExceptions`。
- case 上的 `_狀態`（例如 `"待確認"`）：標這個 case 還沒決定要不要修，跑時用 `--cases=` 挑要修的。

### profiles

依這個專案的驗收裝置設定：每個客戶用的平板可能不同，先看專案紀錄或問使用者，再從 `技術坑.md` 的尺寸表挑。上面範例的 10.2 吋 iPad 只是其中一台。

| 欄位 | 說明 |
|---|---|
| `width`、`height` | 視窗大小（CSS px） |
| `touch` | `true` 時開 `isMobile`、`hasTouch`、iPad Safari UA、`deviceScaleFactor: 2`。腳本會確認 `(pointer: coarse)`、`(hover: none)` 成立，寫進結果 |
| `engine` | `chromium`（預設）或 `webkit` |
| `locale` | 選填，例如 `ja-JP` |

案例可以用 `"profile"` 指定一個尺寸，用 `"profiles": ["a", "b"]` 同時拍幾個尺寸，或直接寫 `"width"`。**檔名一律含 profile：`<案例 id>-<profile>-<before|after>.png`**（例如 `spec-dialog-ipad102-portrait-after.png`；舊版只用 `profile` 時沒有這一段，舊結果不受影響）。

只寫 `width` 的案例：高度用同寬的 profile，沒有就用 `width × 1.4`；`touch`（可用案例的 `touch` 覆寫）、`engine`、`locale` **繼承寬度最接近的 profile**，profile 名是 `w<寬度>`。

**名稱與 id 的限制**：案例 id、頁面 id、profile 名會變成檔名，不能是空字串、`.`、`..`，不能含斜線、反斜線和 `: * ? " < > |`、控制字元，不能以句點或空白結尾；案例 id 之間、頁面 id 之間不可重複（不分大小寫，因為 macOS／Windows 檔名不分大小寫）。中文可以。違反就直接報錯（結束碼 2）；shots 還會在起跑前檢查所有預計輸出的檔名不撞名。

### target（找元素）

依優先順序擇一：

| 寫法 | 說明 |
|---|---|
| `{ "testId": "spec-dialog" }` | `data-testid` |
| `{ "role": "button", "name": "查看規格", "exact": true }` | 無障礙角色＋名稱，最穩 |
| `{ "css": "main .grid a" }` | CSS |
| `{ "text": "聯絡我們", "exact": false }` | 看得到的文字 |

- 可加 `"within": { ...另一個 target }` 限定範圍。
- **看得到的找到 0 個或超過 1 個就算這項失敗**，不自動挑第一個（隱藏的不算，例如響應式重複的導覽連結）。錯誤訊息會列出找到的幾個。**找到 0 個時會列候選**（寫進錯誤訊息；`require` 沒出現時寫進 warnings）：`role` 列同 role 看得見的前 5 個名稱（近似的 accessible name），`text` 列含部分字的前 5 個文字，`css`／`testId` 寫「找不到」；另外若有符合但看不見的，會說有幾個。真的要挑時寫 `"pick": "first" | "last" | 2`（數字從 1 開始，2 是第二個），結果會記下用了 pick。
- 修改前後的網站結構不同時，可以在 `before`／`after` 各寫一份：`"target": { "before": {...}, "after": {...} }`。兩邊要指同一個區塊、同一個操作狀態。

### steps（操作，依序執行）

| action | 參數 | 說明 |
|---|---|---|
| `click` | `target` | 觸控 profile 用 tap |
| `scrollTo` | `target`、`offset`（預設 120） | 把元素捲到距視窗頂 offset |
| `scrollBy` | `y` | |
| `scrollLeft` | `target`、`value`（`"end"` 或數字） | 橫滑區 |
| `waitVisible` | `target`、`timeout` | |
| `press` | `key` | **`Enter` 在輸入框裡會送出表單**，在正式站要小心 |
| `fill` | `target`、`value` | 在輸入框填字（不會按送出） |
| `selectOption` | `target`、`value` 或 `label` | 下拉選單選一項 |
| `check`、`uncheck` | `target` | 勾選、取消勾選 |
| `waitHidden` | `target`、`timeout` | 等元素消失（彈窗關閉、載入中消失） |
| `wait` | `ms` | 最後手段，結果會記下 |

### 案例的說明欄位

| 欄位 | 說明 |
|---|---|
| `note` | 這張拍什麼、為什麼這樣拍 |
| `expect` | **怎樣算修好**（中文一兩句，從專案清單的「描述」「狀態」整理）。shots-report 會原樣印出，驗收的人拿它對照截圖 |
| `kind` | `"visual"`（預設，看畫面）、`"interaction"`（要操作才出現，截圖是操作後的畫面）、`"motion"`（視差、轉場、動畫，靜態截圖證明不了）。`motion` 的報告會寫明「需要動態觀察／錄影」 |
| `profile` / `profiles` | 見 profiles |
| `require` | target 陣列：**這張圖要驗的東西**（例如 `expect` 提到的按鈕、標題）。拍之前每個都要看得見（最多等 5 秒），拍完還要確認它真的落在截圖範圍內；否則這項標 `incomplete`，warnings 寫「要驗的東西沒出現：…」，不能當作通過。元素型截圖的 `capture.target` 本來就必須存在，`require` 主要補 `viewport`／`clip` 型，以及 `expect` 提到截圖目標以外的東西。可以一次寫多個；每個 target 符合多個元素也算（只要有一個看得見） |
| `expectedStatus` | HTTP 狀態碼或陣列（例如 `404`、`[404, 500]`）：這個案例（或 `pages` 項目）的頁面本來就會回這個狀態碼，符合時照常量測、拍照，不當作打不開。專門測錯誤頁用；沒列入的 ≥ 400 仍然失敗 |

### capture（拍法）

| mode | 參數 | 說明 |
|---|---|---|
| `viewport` | — | 目前畫面 |
| `element` | `target`、`padding`（預設 0）、`grow`（`"section"` 往上找到最近的 section） | 元素範圍 |
| `fullPage` | — | 整頁（總覽用；lazy 圖片可能是空的，要細看用 viewport） |
| `clip` | `x`、`y`、`width`、`height`（比例 0–1 或 px） | 畫面某一塊 |

- `hide`：選填，要藏的元素 target 陣列（例如固定頁首）。**預設不藏任何東西**，藏了會寫進結果。
- 區塊比視窗高時整塊拍完，不截斷；超過 4000px 才截（`fullPage` 也一樣，實際只拍前 4000px），並在結果標 `truncated`、warnings 有「超過 4000px 已截斷」。

### motion

`"reduce"` 或 `"no-preference"`（預設）。用 reduce 拍到元素一直透明時，那是網站的缺陷，要另外列；換成一般模式拍只是另一份證據，結果會記下。**有些元素只在一般動態才出現**（例如影片的聲音按鈕，減少動態時影片不播、按鈕不出現）：要驗這種元素的案例用一般動態，並在 `require` 寫上它，減少動態另列一案。

## 拍之前的準備（兩支腳本共用）

1. `goto` 等 `load`，再等 `networkidle`（**最多 3 秒**；`sites.<before|after>.networkIdleMs` 可覆寫，單位毫秒，例如網站很慢可設 8000）。逾時寫進 `notes`（「networkidle N 秒內沒達成」），不算 warnings：預覽站的工具列、分析程式常讓網路一直不停。後面的字型、圖片、版面穩定檢查照舊，所以縮短這個上限不會讓沒載好的圖溜過去。
   - `goto` 逾時或網路錯誤時，**換一個全新的 context 重試一次**（只重試載入，不重播 steps）。成功時 `notes` 記「重試 1 次（第一次：<錯誤>）」；仍失敗才算 fail，錯誤訊息寫「已重試 1 次，第一次：…」。HTTP ≥ 400 不重試。
   - 結束時若有 fail，終端機印一行可直接複製的重跑指令（shots 用 `--cases=<失敗案例>`，sweep 用 `--pages=<失敗頁>`，`--run=<本次名>-retry`，其餘旗標沿用）。
2. 從上捲到底、再回頂端，讓 lazy 圖片和進場動畫觸發。
3. 等 `document.fonts.ready`（最多 10 秒）。
4. 確認畫面內的圖片都 `complete` 且 `naturalWidth > 0`；沒載好的記下來。操作步驟之後，`element`、`viewport`、`clip` 三種拍法都會再對實際要拍的範圍檢查一次（`fullPage` 不檢查）。
5. 等版面穩定：目標元素（或 body）的位置大小連續 300ms 沒變，最多等 5 秒。
6. 截圖先用 `page.screenshot`（15 秒逾時）；Chromium 逾時改用 CDP `Page.captureScreenshot`（`captureBeyondViewport`），結果記 `fallback: "cdp"`。

第 3–6 步沒達成寫進結果的 `warnings`。**有 warnings 的截圖是「證據不完整」，不能當作通過。** 用了 `wait` 步驟記在 `waits`。

## shots.mjs 的輸出

### 情境截圖與前後對比圖（`scripts/lib/context.mjs`）

- 每個 `capture.mode: "element"` 的 case，除了原本的元素截圖，多拍一張**情境截圖** `ctx/<案例>-<profile>-<site>.png`：把元素（含 `grow`、`padding`）捲到距視窗頂約 160px（fixed 頁首下方），拍整個視窗（viewport），記下元素在視窗中的 rect。先多捲 60px 再往上回到位置，讓「往下捲收起、往上捲出現」的頁首會顯示。元素比一屏高時，只拍到元素開頭那屏，`context.taller` 為 true，對比圖底部註明「區塊比一屏高」。`capture.mode: "viewport"` 直接用原圖；`fullPage`、`clip` 沒有要框的元素，不拍。拍不到不影響狀態，只在 `notes` 記一筆。`shots-results.json` 每筆多 `context: { file, rect, viewport, taller, sameAsMain }`。
- **情境截圖不參與像素比對**，比對仍用元素截圖。
- **對比圖** `compare/<案例>-<profile>.png`（2400px 寬，左舊右新）：上方標題列「修改前：<label>」（綠）／「修改後：<label>」（紅），下一行 `網址主機 / 路徑`；兩張圖各用對應顏色框出元素；底部一行 `<案例 id> <note 前 20 字>｜<profile 名> <寬×高>｜框：<區塊>（修改前高 A px → 修改後高 B px）`。區塊名取 `capture.label`，沒有就用 target 的 name／text／testId／css／role。基準的條件不同或證據不完整時，底部用橘字註明。
- 什麼時候產生：`--site=both` 時本次 before 對 after；有 `--baseline` 時，左邊是**基準的 before**（沒有就用基準同 site）、右邊是本次的圖，標題會寫「基準 <run> 的 …」。兩種都有時，基準那張檔名加 `-baseline`。基準是舊版腳本產生的（沒有 `ctx/`）時不產生，報告寫原因。報告每個案例列對比圖連結，「截圖差異」每列也附連結。
- 做法：用 Playwright 在 Chromium 開一頁 HTML 版型再截圖，不需要處理字型。中文字型靠系統：macOS 用 PingFang，Windows 用微軟正黑體，Linux 要有 Noto Sans CJK；找不到中文字型時文字會變成方框，圖仍會產生，要補裝字型。**Linux 沒裝中日韓字型時，不只對比圖的標題，被測網站的中文也會變方框，行數、寬度、溢出都量不準，而且腳本不會報錯**；Linux（含 CI）要先裝 Noto Sans CJK 這類字型（`npx playwright install --with-deps chromium` 只裝瀏覽器需要的系統函式庫，不一定含中文字型）。對比圖合成需要 Chromium 系瀏覽器；只有 WebKit 時量測可以跑，對比圖會記「對比圖產生失敗」，不影響整個 run。
- 拍攝條件雜湊：`condHash`（steps、capture、hide、motion、expectedStatus；`condVersion: 2`）；`require` 另算 `reqHash`，基準的 require 不同只在報告寫「require 改過（不影響截圖範圍）」，不算條件不同。沒有 `condVersion` 的舊基準，用含 require 的舊算法核對。

- 截圖：`<out>/<run>/<案例 id>-<profile>-<before|after>.png`
- `<out>/<run>/shots-results.json`：`{ run, time, baseline, sites, results: [...] }`，每筆：

```json
{
  "id": "spec-dialog", "site": "after", "label": "PR #12 3f52e2b",
  "url": "https://.../products/1", "finalUrl": "...", "httpStatus": 200,
  "kind": "interaction", "expect": "彈窗內容完整顯示，整組置中", "note": "spec-dialog 「查看規格」彈窗",
  "profile": { "name": "ipad102-portrait", "width": 810, "height": 1080, "touch": true,
               "pointerCoarse": true, "hoverNone": true, "engine": "chromium" },
  "motion": "reduce", "status": "ok", "file": "spec-dialog-ipad102-portrait-after.png",
  "rect": { "x": 0, "y": 1200, "width": 810, "height": 980 },
  "path": "/products/1", "condHash": "3f2a9c1b07de", "require": ["{\"role\":\"dialog\"}"], "expectedStatus": null,
  "hidden": [], "picked": null, "truncated": false, "fallback": null,
  "warnings": [], "error": null, "time": "2026-11-04T10:00:00+08:00"
}
```

`status` 是 `ok`、`incomplete`（有 warnings）或 `fail`（有 error）。終端機每項印一行，最後印總數。

- `<out>/<run>/shots-report.md`：給人看的報告。開頭列工具資訊、每個網站的網址、label、版本證據與請求資訊，以及 `--baseline` 指到的資料夾與條件核對結果；之後**每個案例一節**：note、怎樣算修好（expect）、類型（kind；motion 會寫「需要動態觀察／錄影」）；每個 profile 一小節，用表格把（基準的 before／after）和本次各網站的圖並排；下面逐網站列狀態（取證完成／證據不完整／失敗）、warnings、備註（用了 pick、藏了元素、固定等待、網址被轉走）。「取證完成」不等於修好，要人對照 expect 看。
- **基準是局部或全站**：只跑子集的 run 是局部基準，只代表它涵蓋的範圍；拿它去比更大的範圍，會有大量項目「基準找不到」（`--compare` 同理，會出現大量「沒有對照」）。所以局部基準只比同範圍，不取代其他範圍的舊基準；完整驗收時全部重跑，才更新全站基準。雙站（before＋after）的 run 當基準時，對比圖左邊取基準的 before，像素差取同 site 的圖。登記方式見 SKILL.md「修改前後對照」。**報告要在 run 資料夾內開**（圖片用相對路徑，把 md 搬走圖就不見）。
- `--baseline=<舊資料夾名>`：把那個資料夾裡同案例、同 profile 的 `before`、`after` 圖連進表格，並對本次每張圖算差異（見下面「截圖差異」）。常見用法：合併後 `--site=after` 只重拍新版，跟舊 run 的圖比。**會讀基準的 `shots-results.json` 逐項核對條件**：路徑、profile 寬高與 touch、引擎、motion，以及 `condHash`（steps、capture、hide、require、motion、expectedStatus 的雜湊）。不一致的欄位標「**條件不同**」並寫出差在哪；基準裡找不到那一項（案例或 profile 不同）也會列出，不會默默少一欄。基準若是沒有 `condHash` 的舊格式，標「無法核對 steps／capture」。

### 截圖差異（`scripts/lib/imgdiff.mjs`）

**只用來排序「先看哪張」，不判通過。** 沒有任何門檻會讓某一項自動變成「沒問題」。

- 比對對象：有 `--baseline` 時，本次每張圖對基準同案例、同 profile、同 site 的圖（`against: "baseline:<資料夾>"`）；`--site=both` 時本次 after 對本次 before（`against: "before"`）。兩者都有時兩種都算，`diffs` 陣列放全部，`diff` 是第一個（有基準就是基準那個）。
- 先讀 PNG 檔頭（IHDR）比寬高；**尺寸不同就不算像素差**，直接記 `sizeChanged: true`、`from`、`to`。同尺寸才用 `node:zlib` 解碼（8-bit RGB／RGBA、非交錯、filter 0–4，不依賴套件）算像素差。其他格式（調色盤、16-bit、交錯）回 `status: "unsupported"`，報告列在「無法比對」，不會當掉。
- 指標：`ratio` = 亮度差（0.299R+0.587G+0.114B）> 16 的像素佔整張的比例；`regions` = 差異像素的外框，依「空白列間隔 > 40px」切成最多 3 塊（`{x, y, w, h}`，圖片像素）。檔案 md5 相同記 `md5Same: true`（不再解碼）。
- 同尺寸且有差異時，在新圖上畫紅框存 `<run>/diff/<檔名>`（對 before 的另存 `diff/vs-before-<檔名>`），報告連結「差異圖」。
- `shots-results.json` 每筆多 `diff`（第一個）與 `diffs`：`{ against, status, md5Same, sizeChanged, from:[w,h], to:[w,h], ratio, regions, oldImage, diffFile }`。
- 報告新增一節「截圖差異（依差異排序）」：先「尺寸不同」（寫原尺寸→新尺寸）；再「差異 ≥ 0.5%」由大到小，每列附舊／新／差異圖連結、比例、差異區域；「差異 < 0.5%」只列數量和編號，並寫「差異小不代表沒問題，小元素消失可能佔不到 0.5%，要抽看」。
- **前後幾乎相同警告**：`--site=both` 時，若 ≥ 50% 的 before／after 對差異 < 0.1%（或 md5 相同），終端機與報告開頭印粗體「修改前後幾乎相同（N／M 對），請先確認兩個網址是否真的是不同版本」。
- **基準網址警告**：報告開頭列基準 run 的 sites（url、label、產生時間）；基準任一 site 的 url 和本次任一 site 的 url 相同時警告「基準和本次用了同一個網址，網址可能已經指到新版本，前後對照可能失效」。
- 限制：只比同名圖；元素截圖的高度會隨內容變，高度不同就只報尺寸；動畫、輪播、影片、字型載入時序可能造成小比例差異。
- 測試：`node scripts/test/imgdiff.test.mjs`（合成圖）；加參數 `<out> <基準 run> <對照 run>` 再跑真實資料。

## sweep.mjs 量什麼

每頁每個 profile 量一次（`--profiles=a,b` 只量指定的；指定後預設不量斷點，要量加 `--with-breakpoints`，不要斷點加 `--no-breakpoints`；`--pages=id1,id2` 只量指定頁）；另外每個斷點 b 量 `b−1`、`b`、`b+1` 三個寬度（同一個分頁直接改視窗大小，才能追蹤同一個元素；**每換一次寬度都會重做準備：捲到底再回頂、等字型、檢查圖片、等版面穩定**，所以第 2、3 個寬度的內容也已觸發進場動畫）。高度用設定檔裡最接近寬度的 profile 的高度。低於 `tabletMin` 的寬度見上面的 tabletMin。

**sweep 產生的是「待看的線索」，不是缺陷判定、也不打美感分數。** 每條線索都要人看截圖確認。

檢查項目共十種（`overflow`、`clipped`、`scrollbox`、`shortLastLine`、`lineJump`、`sizeJump`、`tap`、`invisible`、`fixedCover`、`env`；`env` 不能關）。`--checks` 可只跑其中幾種，各自怎麼量見文件最後的「附錄：量法」。

行數用 `Range.getClientRects()` 依每個矩形的 top 分組算，不要用「高度 ÷ line-height」。隱藏的、螢幕閱讀器專用（寬或高 ≤ 1px）的文字不算。

### 分類、分組（先分類，再限制數量）

原始線索**全部**留在 `sweep-results.json`，沒有上限。報告前先分類：

| 類別 | 條件 |
|---|---|
| 已接受 `accepted` | 符合 `acceptedExceptions`（見下） |
| 手機版參考 `reference` | 量測寬度低於 `tabletMin`（沒被例外吃掉的線索） |
| 進場動畫時間差 `timing`（參考） | `invisible` 線索中，符合任一條：①量測時元素的祖先（含自己、不含已經是 0 的那層）`opacity` 介於 0.05–0.99（淡入進行中，線索標 `fadingIn`）；②取證重測時已看得見（證據圖註明「取證重測時已看得見」，該元素在所有寬度的線索一起移過來）。不進主清單，報告「進場動畫時間差（參考）」段列數量與前 8 組，`sweep-groups.json` 每個網站多一個 `timing`（編號 T01…，從「需要看」移來的保留原編號的證據圖，主清單編號不重排）。只有取證過的組（前 40 組加新出現的）會走②；沒取證的靠①。 |
| 內捲區 `scrollbox`（走「要看」） | 直向 `overflow-y: auto／scroll`、`scrollHeight > clientHeight × 1.1`、不在 `[role=dialog]`／`dialog` 內。描述「內容 N px、框 M px，要確認看得出還有內容、最後一項到得了」。這種元素不再重複算成 `clipped` 的刻意設計；只有橫向可捲動、省略號、line-clamp 仍算刻意 |
| 切換堆疊 `stack`（參考） | `invisible` 且元素（`opacity: 0`）的同父層兄弟中，有一個位置、大小（±2px）相同且 `opacity ≥ 0.99`（輪播、tab、淡入淡出）。不進主清單，報告「切換堆疊（參考）」段與摘要只列數量 |
| 刻意設計 `intentional` | ①`tap` 命中別的 `a[href]` 但 href（去 hash）、`target`、`download` 都相同、且同在一張卡（共同祖先在 3 層內，或同在一個 `article`／`li`）：同連結的外層覆蓋，點旁邊一樣有效，線索標 `sameHrefCover: true`，描述「旁邊是同一連結的外層覆蓋，實際可點」（量測時 others／stolen 也不把它當別人）；②`invisible` 且自己或祖先 `pointer-events: none` 且 `opacity: 0`（不接收點擊的透明層）；③`clipped` 且**每個實際有超出的方向**都有對應的刻意處理：橫向看可捲動（`overflow-x`）、省略號；直向看可捲動（`overflow-y`）、line-clamp；重複文字（hover 動畫）兩個方向都算。X、Y 分開判斷：橫向可捲動、但直向文字被切掉，仍是「要看」，描述會寫「橫向可捲動是刻意的，但直向沒有對應處理」 |
| 環境 `env` | 觸控環境不成立，點擊範圍不可信，摘要裡警告 |
| 要看 `review` | 其他 |

只有「要看」進主清單，並分組：同檢查、同元素（選擇器＋文字）在不同寬度、不同頁面合併成一組，列出出現的頁面與寬度、最差的那一個值。第二輪再合併三種情況，每組的 `members` 保留所有成員（selector、位置、profile、頁面、寬度、原始紀錄索引 `record`）：

- **同一父層的兄弟**（同頁同寬度、同檢查、同描述、只差 `nth-*`）合成「同類 N 個」。**不同區塊的同名元件（父層不同）不會合併**。
- **tap 重疊**：同一父層、連續並排的重疊合成「同列 N 個」（描述不含鄰居名字）。
- **跑馬燈等套件複製的元素**（祖先 class 含 clone、duplicate、marquee 的 aria-hidden 複本，或 `data-clone`；同標籤、同大小、同 src 或同文字）合成一組。
- 子元素的框和父元素一樣大（例如 `a` 裡的 `button`）只留父元素。

嚴重度排序：橫向溢出 → 文字被裁切（無備註）→ 內捲區 → 點擊重疊 → 點擊太小 → 捲完還透明 → 行數／尺寸突變 → 固定列 → 最後一行太短。

**每一組的寬度是「有量到問題的離散測點」，不代表中間的寬度都驗過。**

### acceptedExceptions

`page` 可以是一頁、頁面陣列或 `"*"` 全站；`check` 要同；`match`（選填，不寫就吃該頁該檢查的全部）有三種寫法：

| 寫法 | 比對方式 |
|---|---|
| `"字串"` | 元素文字（前 40 字）**完全相等**，或元素的標籤名、id、class、`data-testid` 其中一個**完全相等**（不是子字串，`"select"` 不會吃到 class `selected`） |
| `{ "css": "select" }` | 元素本身符合這個 CSS 選擇器（量測時用 `element.matches`）。例如 `[id^="product-tab-"]` |
| `{ "text": "分類標籤" }` | 元素文字（前 40 字）**包含**這段 |

腳本只讀 `check`、`page`、`match`、`min`、`reason`。`check` 名稱和 `page` id 不驗證，寫錯不報錯，只會配不到。不能限定寬度或 profile。符合的線索移到「已接受」，原始證據保留。

可選的 `min`（只支援 `check: "tap"`）：只有量到的點擊範圍（寬、高取小的）≥ `min` 才接受，例如 `{"min": 40}` 的 42px 分頁縮到 20px 就不再被接受。**跟鄰近目標重疊、中心被蓋住的線索永遠不吃尺寸例外**，一律回到主清單。沒寫 `min` 就不限尺寸，建議都寫。

### sweep 的輸出（`<out>/<run>/`）

- `results/<頁面 id>.json`：該頁所有網站、所有寬度的**完整原始紀錄**（每頁一個檔，避免全站結果擠成數百 MB 的單檔）：`{ page, records }`，每筆含 `httpStatus`、環境、`warnings`、`skipped`（例如沒量 tap）、`reference`（是否手機版）、`findings`（每條：`check`、`selector`、`text` 前 40 字、`rect`、數值、`cls`、`reason`；另有 `tokens`、`matches`、`pid`、`sig`、`clone` 給例外比對與分組用）。tap 的數值含 `hitW`、`hitH`（命中寬高）。
- `sweep-results.json`：總表 `{ run, time, args, minTap, tabletMin, sites, tool, files, records }`；`files` 是頁面 id → 上面的檔，`records` 每頁每寬度一筆（同寬度的 profile 紀錄與斷點紀錄各一筆），欄位同上但 `findings` 改成 `findingCount`，並有 `idx`（全表索引）與 `file`。
- `sweep-groups.json`：分組結果，每個網站有 `review`（主清單）、`reference`（手機版參考）、各類別數量與 `byReason`（已接受／刻意設計，每個原因記 `elements`、`widths`、`count`）；每組有 `id`（G01…；參考段是 R01…）、檢查、頁面與寬度、最差值的中文描述、證據圖路徑、`members`。給後續 session 用。有比對時，被比對的網站多一個 `compare: { against, label, newCount, sameCount, noBaselineCount, noBaselinePages }`，`review` 每組多 `compareStatus`（`new`／`same`／`noBaseline`），每個 `pages` 項目多 `status`（同三個值）。
- `evidence/<site>/G01-<檢查>-<頁>-<寬度>.png`（雙站各一個資料夾，不會互相覆蓋；檔名保留中文）：**前 40 組，加上所有「固定列佔高」**（不受 40 組上限擠掉）各一張代表截圖：在最差寬度重開頁面，找到元素，畫紅框，裁出元素外加約 48px 的範圍（至少 360×220）。整頁橫向溢出（`html`）畫在視窗右緣。找不到元素時用記錄的位置畫框；拍不到就寫「證據圖拍不到」。有比對時，「這次新出現」的前 40 組也一定拍（跟前 40 組取聯集）。`invisible` 的證據圖會重新找元素並重測：重測時已看得見，報告會註明「原量測出現，取證重測時已看得見，未重現」。
- `sweep-report.md`（中文）：
  1. **摘要**：各類別數量；寫明「機器量完」（也就是 ✓）只代表腳本量完、視覺尚未確認。
  2. **覆蓋表**：頁面 × 欄，欄是「寬度（profile 名）」或「寬度（斷點）」，同寬度的 profile 紀錄和斷點紀錄各一欄，欄數加總 = 量測筆數；格子是「機器量完」「證據不完整」「打不開（HTTP n）」。
  3. **這次新出現／沒有對照**（有比對時才有，在被比對的網站段落、「需要看」之前）：見下面「新舊比對」。摘要多一行「新出現 N 組／原本就有 M 組／沒有對照 K 組」。
  4. **需要看**（有比對時標題改成「需要看（含原本就有的，共 N 組；其中 M 組舊版本也有）」，完整清單不刪）：分組清單，一組一行（頁面、寬度、檢查、元素文字、最差值、證據圖）；有文字的元素不印選擇器，沒文字的才印最多 60 字的短選擇器。最多列 80 組，其餘在 JSON。
  5. **手機版（參考）**：低於 `tabletMin` 的線索（有才有）。
  6. **已接受／刻意設計**：依原因列「N 個元素 × M 個寬度（共 K 條）」。
  7. **進場動畫時間差（參考）**（有才有，見上面分類表）。
  8. **切換堆疊（參考）**（有才有）：不進主清單的堆疊透明項。摘要另有一行列出「切換堆疊」與「同連結外層覆蓋」的條數。報告開頭寫這次跑的檢查與沒跑的檢查。
  9. **沒量的**：範圍、彈窗與展開狀態、沒量 tap 的 profile、不納入的元素、證據圖上限。

## 新舊比對（`--compare`、`--site=both`）

目的：全站 sweep 會有上百組「需要看」，回歸驗收只該先看「新版本才有」的。

- **何時比**：`--site=both` 時 after 自動對本次的 before；`--compare=<run>[:<site>]` 時 after（沒有 after 就是第一個網站）對舊 run 的 `<out>/<run>/sweep-groups.json` 與 `sweep-results.json`。site 沒寫：有跟被比對網站同名的用同名，否則用 `after`，再否則用唯一的那個。**兩者同時用以 `--compare` 為準**（before 照量但不拿來比，報告會註明）。找不到資料夾或檔案、舊 run 沒有那個 site，就在起跑前報錯停下（結束碼 2）。
- **比對單位**（第三輪改成逐寬度）：**頁＋寬度＋檢查＋元素鍵**，元素鍵 = `selector` 去掉所有 `:nth-*(...)` ＋ `text` 前 10 字（tap 的檢查再分 size／overlap）。舊版本資料來自舊 run 的 `sweep-results.json` 與 `results/<頁>.json`（要完整紀錄，不是只看 `sweep-groups.json`），只收舊版本 `cls` 為 `review` 的線索。每條線索按（頁、寬度）分類：
  - `new`（這次新出現）：舊版本同頁同寬度有量（status `ok`），沒有這一條。
  - `worse`（變差）：同鍵，但數值明顯變差——tap 點擊範圍變小 ≥ 4px、clipped 超出量增加 ≥ 8px、fixedCover 佔比增加 ≥ 5 個百分點；其他檢查不判惡化。
  - `same`：同鍵、沒有明顯變差。
  - `textChanged`（只有文字變了）：同頁同寬度同檢查同 selector，只有 text 前 10 字不同，一對一配對；不算新出現，列在新出現後面。
  - `noBaseline`（沒有對照）：舊版本那頁那寬度沒量、失敗、或證據不完整（status 不是 `ok`）。
  - `better`：舊有新無，只計數（本次沒跑的檢查不計）。
  一組的狀態：任一格 `new` → new；否則任一格 `worse` → worse；否則 `textChanged`；否則 `same`；全部是 `noBaseline` 才是 noBaseline。
- **覆蓋缺口從「預計量測矩陣」算，不從線索清單推**：本次每個（頁、寬度）若舊版本沒有 `ok` 的紀錄，這格就是 noBaseline，**不論有沒有線索**都列在報告「沒有對照」的頁／寬度清單裡（本次自己失敗的格子不重複列，覆蓋表已標）。noBaseline 不算新出現，也不代表沒問題，要直接看。
- **量測條件相容性**：比對前核對兩邊的工具版本（Playwright、瀏覽器、腳本雜湊，只警告）、`tabletMin`、`minTap`、每頁 `path`；不同就在報告寫「**條件不同：…**」（`sweep-groups.json` 的 `compare.conditions` 也記）。
- **報告**：「這次新出現」全部列出（不受 40 組上限，證據圖仍最多 40 張）；另有「變差」「只有文字變了」「沒有對照」。`sweep-groups.json` 的 `compare` 欄位：`newCount`、`worseCount`、`textChangedCount`、`sameCount`、`noBaselineCount`、`betterCount`、`noBaselineCellCount`、`noBaselinePages`（頁 → 寬度與原因）、`conditions`；每組 `compareStatus`（`new`／`worse`／`textChanged`／`same`／`noBaseline`）、`pages[].status` 與 `pages[].statusByWidth`、變差的 `compareDetail`。
- **限制**：選擇器（class 名、層級）改了，會被當成新的；文字前 10 字只有同 selector 才會被配成「只有文字變了」。舊版本把某線索分類成已接受／刻意設計、新版本變成需要看，也算新出現。只比「需要看」，不比手機版（參考）。同一寬度的 profile 紀錄與斷點紀錄合併成同一格；只要其中一筆是 `ok` 就能當對照。
- 瀏覽器備援測試在 `scripts/test/browser-pool.test.mjs`（用假的 playwright 物件，不開瀏覽器）；整組不需瀏覽器的測試用 `npm test`，需要瀏覽器的量測測試用 `npm run test:browser`。
- 純函式在 `scripts/lib/compare.mjs`，測試在 `scripts/test/compare.test.mjs`（`node scripts/test/compare.test.mjs <含 before、after 的 run 資料夾>`）。

## 已知限制

- 交界比對靠量測時在元素上加的 `data-tqa` 標記；框架在改寬度時重新渲染的元素會比不到，直接跳過。
- 比視窗高的元素截圖用整頁座標裁切，裡面的 fixed／sticky 元素位置可能不對；需要時用 `hide`，或改用 viewport 分段拍。
- WebKit 沒有 CDP，截圖逾時就是失敗，沒有備用方法。
- 代表截圖是重開頁面再找元素，載入時序不同可能找不到或位置稍有差異；以 JSON 的 `rect` 和數值為準。
- 斷點寬度（b−1、b、b+1）的證據圖是直接以該寬度開頁，不是量測時「同一頁改視窗」的狀態。
- 點擊範圍的命中測試會對齊整數像素，量到的值可能差 1px（42px 的按鈕可能顯示 43）；判斷 44 附近的值時看元素和 `::before` 的 computed 高度。
- 量點擊範圍時會橫捲裡面的輪播，同一個寬度後面的量測可能受影響。
- 頁面轉址或換語系不會特別處理；看結果裡的 `finalUrl`。
- `shortLastLine` 只在「最後一行寬度 `lw` < 塊寬 `bw` × 0.5」時才檢查，再要求 `lw < bw × 0.15` 或只有 1–2 個字素；最後一行很長但只比一半略短的不會列。
- 點擊範圍的取樣：5×5 點落在 `minTap` 方框內側 1px（瀏覽器命中測試會把座標對齊整數像素），所以兩個緊貼的 44px 元素只是邊界相接，不算重疊；小於 1–2px 的重疊也量不到。
- 同寬度的 profile 紀錄和斷點紀錄是兩次不同的載入，分組時視為不同來源。

## 附錄：量法

| 檢查 | 代號 | 量法 |
|---|---|---|
| 橫向溢出 | `overflow` | `scrollWidth > innerWidth`；列出超出視窗、祖先也沒有裁切的元素 |
| 文字被裁切 | `clipped` | 有文字、`overflow` 不是 visible、`scrollWidth > clientWidth + 1` 或 `scrollHeight > clientHeight + 1`。故意的（可捲動、省略號、line-clamp、hover 動畫的重複文字）加註記，報告裡排在後面 |
| 最後一行太短 | `shortLastLine` | 至少兩行的文字塊，最後一行寬度不到塊寬 15%，或只有 1–2 個字素（用 `Intl.Segmenter`）。行內元素用最近的區塊祖先寬度。附最後一行文字 |
| 行數突變 | `lineJump` | 同一文字塊在 `b−1`、`b`、`b+1` 的行數差 ≥ 2 |
| 尺寸突變 | `sizeJump` | 圖片、影片、按鈕在 `b−1` → `b` 寬或高變成 1.5 倍以上或 2/3 以下 |
| 點擊範圍 | `tap` | **只量 `touch: true` 的 profile**（桌機 profile 不量）。可點元素（有 href 的 a、button、`[role=button]`、input、select、summary、`tabindex ≥ 0`）：從中心往上下左右每 0.25px 用 `elementFromPoint` 量命中寬高（含 `::before` 擴大的範圍）；另在中心周圍 `minTap × minTap` 取 5×5 點，看有沒有打到鄰近的其他可點元素。命中寬或高小於 `minTap`、或跟鄰近目標重疊就列。中心捲不進畫面的跳過。先照嚴格規則量；有問題且目標是 `a[href]` 時，再把「同連結外層覆蓋」算命中重量一次，這次沒問題就記 `sameHrefCover`（見分類） |
| 內捲區 | `scrollbox` | 見上面分類：`overflow-y` 可捲動且內容高於框 10% 以上、不在彈窗內 |
| 捲完還透明 | `invisible` | 捲到底再回頂端之後，有文字、不在 `aria-hidden`／螢幕閱讀器專用、但自己或祖先 `opacity: 0` 或 `visibility: hidden` |
| 固定列佔高 | `fixedCover` | 往下捲 600px 後，頂端 fixed／sticky 元素聯集高度 ÷ 視窗高；超過 25% 列出（整屏 sticky 的主視覺會是 1.0，看截圖排除） |
| 觸控環境不成立 | `env` | `touch: true` 但 `(pointer: coarse)` 或 `(hover: none)` 不成立 |

補充：

- 點擊範圍（`tap`）的重疊分三種，**只有前兩種會列**：①別人的可點元素蓋在自己的框內（真重疊）；②自己的擴大點擊區（例如 `::before`）蓋到別人的框內，搶走對方的點擊（描述寫「擴大的點擊區蓋到旁邊的可點元素」）；③只是邊界剛好相接，不算。
- `clipped` 的 X、Y 兩軸分開判斷（見上面的分類）。
- `invisible` 的證據圖會重測，原量測是「換寬度後尚未觸發進場動畫」造成的假線索，現在換寬度會重做準備，不再出現。
